Getting started

  1. Check queue names and rates under Menu → Queue Settings.
  2. Build today's plan under Menu → Schedule.
  3. Select the queue you are actually working on from the main screen.
  4. For every finished application, enter its UID, choose an outcome, and select App Completed.
  5. Export the completion history before resetting if you need an external record.
Recommended: choose Save Current Plan once the initial plan is ready. This gives End Day Review a fixed start-of-day comparison.

Main screen

Pace timer
Time until the next evenly spaced target beat in the current scheduled segment. When a beat passes, the timer moves directly to the next one, keeping the planned rhythm moving.
ETC
The local clock time at which the next target is due.
Target
The next target number and total target for the segment, such as 2 / 5.
Tracking since
When the manually selected live queue began; otherwise the tracker follows the current plan.
Queue / UID / Outcome
The fields used to record a completion. Changing Queue also records a live queue switch.
Day Overview
A timeline of planned segments with completed-versus-expected values, plus productive time, non-productive time, and completion count.

Schedule

Open Menu → Schedule. Set shift start and end, then use + Add activity. Choose a queue/activity and start time for each row.

  • A segment runs from its start until the next segment starts. The last segment runs until shift end.
  • The default day is 11:00–19:30 with a 15-minute Team briefing.
  • Each start must be inside the shift, and two activities cannot share the same start.
  • Rows are sorted chronologically. Deleting a row causes the preceding activity to run until the following row.
  • Changing the live queue on the main screen does not rewrite the schedule; this separation supports adherence reporting.

Close the dialog to validate it. Invalid shift bounds, out-of-range starts, or duplicate starts must be corrected first.

Queue settings

Open Menu → Queue Settings to create, edit, or delete queue definitions.

Add a queue

  • Queue name: the label shown throughout the dashboard.
  • Apps per hour: the expected throughput. Decimal values are accepted. A rate of zero makes the entry non-productive and creates no app targets.
  • Colour: identifies the queue in schedule and timeline displays.

Edit and delete

Use a queue row's controls to edit its name, rate, or colour. A queue cannot be deleted while today's plan uses it.

Built-in activities: Non-productive, Off queue, and Team briefing are locked at zero apps/hour. They cannot be renamed or deleted, although their colours can be changed.

Live queue tracking

The plan says what was scheduled; the live selection says what you actually worked. Change the main Queue selector, or use a productive timeline segment's tracking shortcut, when work moves.

Each explicit change records the time, selected queue, planned queue/segment, and change source. Menu → Plan Details shows recent switches and whether they matched the plan. End Day Review includes the adherence history.

Non-productive queues cannot be selected for completed work. If no manual selection exists, the active queue falls back to the currently planned segment.

Recording completions

  1. Choose the productive queue that handled the application.
  2. Enter a non-empty application UID.
  3. Select Approve, Resubmit, Decline, Refer to ORE, or Other.
  4. Select App Completed.

The entry stores its timestamp, chosen queue, current planned segment, and when live tracking of the selected queue began. The UID and outcome fields clear after a successful entry.

Use Menu → Completed Apps to review today's entries and delete mistakes. Deletion changes totals and cannot be undone except through a previously preserved external record.

Targets and timer

A productive segment's raw expectation is its hours multiplied by its queue's apps-per-hour rate. Any positive result is rounded up to a whole app. Target due times are spread evenly from segment start to segment end.

On the Day Overview timeline, the target-adjustment control reduces a segment's rounded requirement by one; selecting it again restores the app. The result never falls below zero. This is stored with the segment and is reflected in the timer, reminders, totals, details, and review.

The timer shows no active target before/after the shift, during zero-rate activities, or after every slot in the current segment has passed. Near the last scheduled target, a one-time Final App overlay appears for that segment.

Notification settings

Open Menu → Notifications.

Enable scheduled target reminders
Turns the periodic due-target checks on or off.
Enable browser notifications
Requests native notification permission. Permission may be granted, denied, or unavailable depending on browser and origin.
Send test
Sends an immediate sample using the best available notification mode.
Play a sound
Generates a short reminder tone. Browsers may require a user interaction before audio is allowed.
Keep the tab open. This static application has no service worker or background scheduler. Native notifications are least reliable from file://; serving the folder from http://localhost is recommended. If native delivery is unavailable, an in-page toast is used.

Other menu features

Archived Days
Lists data copied into browser storage by previous resets. Archives are convenient history, not an external backup.
Save Current Plan
Deep-copies queues, segments, shift, and expected total as the start-of-day baseline. Saving again replaces the earlier baseline.
End Day Review
Compares completions with the current expected total, shows variance and start expected total, and lists the start plan, queue adherence, and current plan.
Plan Details
Shows the live tracker, current segment progress, and queue-by-queue planned hours, expectations, completions, and switches.
Export CSV
Downloads one row per current completion. It does not export all archive or activity-log data.
Reset Day
Archives the current day and clears today's operational records while retaining queue settings and preferences.

Reset and date rollover

Reset Day asks for confirmation. It archives the current queues, plan, completions, activity log, switches, snapshot, and shift. It then restores the default shift and Team briefing and clears live day data. Queue definitions, notification preferences, and older archives remain.

If the page remains open across a local calendar-date change, a dialog offers:

  • Export CSV & reset: export when completions/switches exist, archive/reset, and open the new schedule.
  • Reset without export: archive/reset immediately and open the schedule.
  • Skip for now: keep the existing data, mark it as today's state, and open the schedule.
Before resetting: export the CSV if an external completion record is required. Browser archives can disappear when site data is cleared.

Storage, privacy, and exports

State is stored as JSON in browser localStorage under queuePerformanceDashboard.v2. Nothing is uploaded by this app. Storage belongs to the current browser profile and origin, so local-file, localhost, different ports, different browsers, and private windows may not share data.

The CSV contains UID, selected queue, outcome, recorded time, live-queue selection time, planned queue, and planned segment. Treat UIDs and exports according to your organisation's data-handling rules. See the data dictionary for the complete schema and calculations.

Troubleshooting

No pace timer or target

Check that local time is within a scheduled productive segment, its queue rate is above zero, and a future target slot remains.

Notifications are missing

Enable reminders, keep the tab open, try Send test, allow browser permission, and serve from localhost. Check operating-system notification settings and browser audio restrictions.

Schedule will not close

Ensure shift end follows shift start, every activity starts inside the shift, and no two rows use the same time.

Cannot delete a queue

Built-ins are permanent. For another queue, first change or delete every current schedule segment that references it.

Previous data is missing

Return to the same browser profile and URL/origin. Check whether site data was cleared or private browsing was used. The application has no cloud recovery.

CSV will not export

There must be at least one current completion. Browser download policies can also block automatic downloads.
